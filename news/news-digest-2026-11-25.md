**6. Gemini 预览 Tool Retrieval：长尾工具先报名字，要用再取完整 schema**
11 月 24 日，Google 在 Gemini API 的 Interactions API（v1beta）里预览 Tool Retrieval：请求中加一个 tool_search，并把长尾函数或整个 MCP server 标成 defer_loading，模型先只看到名称与短描述，需要时再取完整参数 schema。官方建议工具少于 20 个时仍用静态加载；服务端检索在一次调用内完成，客户端检索则每次多一个往返，且多轮对话仍要每次重传完整 tools 数组。对同时接入多个 MCP server 的代理，这项改动直接决定每轮请求要带多少工具定义，省下的是初始上下文，不是状态管理。

**7. Apex Verify 用另一个模型补检查：错误拦截率 75% 升到 91%**
11 月 22 日发布的 Apex Verify 用“另一个模型”给 AI 改动补写缺失检查：先把任务交给与编码代理不同的模型生成断言，再证明这些断言在旧代码上会失败，最后在新代码上运行并给出 ready、not ready 或 unknown。它还会扫描测试被删除、跳过或只跑 .only 等作弊痕迹；项目以 Apache-2.0 开源，官方在 23 个真实开源库的 200 个 AI 改动上测得：原有测试与作弊扫描拦截 75% 的错误改动，加上它后升到 91%；整体误拦率为 23%，其中 11 个百分点来自项目原有测试，所以 ready 是强证据而不是正确性证明。
[原文](https://github.com/apex-engine-dev/apex-verify)
