## 是什么

Rust 的 async 函数不是"启动一个后台线程"，而是被编译成一个实现了 `Future` 的状态机。调用 async fn 只是构造这个值，函数体一行都不会执行；只有执行器调用 `poll`，它才从上次挂起的状态继续往前。一句话直觉：Future 像一份写好了步骤的剧本，运行时才是导演，不喊"开拍"就没人动。

异步运行时是"执行器 + 反应堆 + 定时器"的合称：执行器管哪些任务可以跑、在哪个线程跑；反应堆把 epoll、kqueue、IOCP 上的就绪事件翻译成"唤醒某个任务"；定时器负责超时与 sleep。典型场景是高并发网络服务、数据库客户端，以及资源受限的嵌入式异步。Rust 标准库只定义 `Future` trait，不带运行时，这是它和 Go、Node 最不一样的地方：语言给你零件，装配方式由你选。

## 核心原理

**async fn 先被拆成状态机。** 编译器把函数体切成若干状态，每个 `.await` 是一个可能的分界点；跨 await 还要用的局部变量会被搬进状态机的字段。因此 Future 的大小在编译期就确定，通常不需要额外堆分配；但反过来说，一个跨 await 持有的大数组或大缓冲区，会把整个 Future 撑大，哪怕它只在一小段里用到。

```rust
async fn fetch(url: &str) -> Result<String, reqwest::Error> {
    let resp = reqwest::get(url).await?;   // 挂起点 1
    let body = resp.text().await?;         // 挂起点 2
    Ok(body)
}
```

调用 `fetch("...")` 只得到一个 `impl Future`，请求并没有发出。要它跑，得 `.await`、交给执行器，或者 `spawn`。

**poll 的契约是理解一切的关键。** [`Future` trait](https://doc.rust-lang.org/std/future/trait.Future.html) 只有一个必须实现的方法：

```rust
fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
```

它返回 `Ready` 或 `Pending`。`Pending` 的语义不是"我等着，你过会儿再来"，而是"我已经把 Waker 登记到事件源，事件到了它会叫我；在那之前别再 poll 我"。如果实现返回了 Pending 却没有保存或注册 Waker，任务就永远醒不过来，表现是挂死而不是报错。标准库文档写得很直白：Future 本身是惰性的，必须被主动 poll。

**执行器、反应堆与唤醒构成主循环。** 执行器维护就绪队列：任务被唤醒就入队，worker 取出后调用 poll，跑到 Pending 就换下一个。反应堆在底下把 socket 注册进 epoll，等可读事件到达，调用之前存下的 `Waker::wake`，把任务重新放回队列。poll、wait、wake 这三步就是异步运行时的心跳（[Waker 的三段式说明](https://without.boats/blog/wakers-i/)）。Tokio 的 `Runtime` 把 I/O driver、scheduler、timer 打成一个包，[`#[tokio::main]` 默认建的就是多线程运行时](https://docs.rs/tokio/latest/tokio/runtime/index.html)。

多线程运行时默认按核心数起 worker，每个 worker 有本地队列；本地队列空了，就去别的 worker 那里偷一半任务，这就是 work-stealing。任务在 await 点可能被挂起，再被另一条线程接着跑，所以它更像"可以换线程的协程"，而不是绑死在某条 OS 线程上的函数。

**Pin 是为自引用状态机准备的安全带。** 状态机里可能保存指向自己字段的引用，比如跨 await 借用了局部变量；一旦 Future 被移动到新地址，这些引用立刻悬空。Pin 给编译器的保证是：被 pin 住的值从 pin 那一刻到 drop 之前不会再被移动。`Box::pin` 把它固定到堆上，`tokio::spawn` 则把 Future 放进堆上的任务结构里。`Unpin` 表示"这个类型即使被 pin 也可以安全移动"，大多数普通类型都是 Unpin，async 块通常不是。这里最常见的反转是把 Unpin 理解成"不能被移动"，意思正好相反。

**spawn 的约束来自任务会换线程、也会活过当前栈。** [`tokio::spawn`](https://docs.rs/tokio/latest/tokio/task/fn.spawn.html) 要求 future 满足 `Send + 'static`：Send 是因为任务可能被工作窃取到另一条线程；'static 是因为任务的生命周期不受调用栈约束，不能借用栈上的局部变量。文档还特别说明，spawn 不会同步 poll，它把任务放进队列就返回 `JoinHandle`；而 `JoinHandle` 被 drop 只是解除等待，并不会取消任务。

**阻塞为什么是运行时的大敌。** 执行器靠"poll 很快返回"来保证公平。某条 worker 上如果有 Future 在 poll 里做了两百毫秒的同步读文件或密集计算，这条 worker 上的其他任务就全部排队；多线程运行时默认 worker 数等于核心数，几个阻塞调用就能把整个运行时按住。Tokio 的任务调度是协作式的，任务之间没有抢占：一个不 await 的死循环可以永久占住一条 worker。

## 常见考点与误区

- **"调用 async fn 就开始执行了"**：错。它只返回 Future；不 await、不 spawn、不 poll，函数体一行都不跑。Rust 的 Future 是惰性的，和 JavaScript 里创建即执行的 Promise 不是一回事。
- **"await 会阻塞线程"**：错。await 是把当前任务挂起、把控制权交回执行器，线程可以去跑别的任务。真正阻塞线程的是在 poll 里做同步 I/O、`thread::sleep` 或长计算。
- **"async 就等于多线程并行"**：错。async 首先解决的是并发调度与等待，单线程运行时也能同时挂起上万个任务；要并行仍得有多个 worker，而且 CPU 密集任务不会因为套了 async 就变快。
- **"tokio::spawn 像 thread::spawn，可以随便借用局部变量"**：错。`Send + 'static` 会直接拦下借用栈上数据的写法；跨 await 持有 `Rc`、`RefCell` 这类 `!Send` 值同样编译失败。
- **"Pin 是语法糖，Unpin 表示不能移动"**：反了。Pin 防的是"已被 poll 的 Future 再被移动"，Unpin 恰恰表示移动无害。手写 Future 时用 `Pin::new_unchecked`，不移动的保证要自己扛。
- **"drop JoinHandle 就会取消任务"**：错。drop 只是 detach；取消要 `abort` 或 drop Future。drop 一个挂起中的 Future 会立刻结束它并执行 Drop，而 `abort` 只是发请求，要等任务下一次让出才生效，正在跑的同步代码不会被打断。
- **"运行时可以随便嵌套 block_on"**：在 Tokio 的异步上下文里再调用 `Runtime::block_on` 会 panic；一个进程也不该按请求创建运行时。

## 实践建议

- **运行时在程序边界创建一次。** main 里用 `#[tokio::main]` 或显式 `Runtime`，库代码尽量只依赖 Future trait，别把 tokio 泄漏进公共 API；确需绑定时在文档里写清，避免下游被迫接受同一套运行时。
- **阻塞调用一律隔离。** 短小的同步 I/O 用 [`spawn_blocking`](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html)，长驻循环用 `std::thread`；CPU 密集任务限制并发数或交给 rayon，别直接塞进 async 任务。`spawn_blocking` 的线程池也有上限，用光了照样排队。
- **控制并发与背压。** spawn 很便宜但不是免费，每个任务都有分配与调度成本；用 `Semaphore` 限制在途请求，用有界 channel 把压力传回上游，别让入口无界地 spawn。
- **分清两种锁。** `std::sync::Mutex` 只保护不跨 await 的短临界区；要跨 await 持锁就用 `tokio::sync::Mutex`，并尽量缩小持锁范围，别在锁里等网络。
- **选对运行时形态。** 普通网络服务用多线程；只需要少量 I/O，或要跑 `!Send` future 时用 current-thread 加 `LocalSet`；不要在 worker 里再起一套运行时。
- **把取消与退出当一等公民。** 用 `CancellationToken` 或 `select!` 响应关闭信号；注意 `select!` 会 drop 落败分支，要评估每个 future 的取消安全性，并给在途任务留出清理时间。

*一句话总结：Rust 的 async 只提供可暂停的 Future，真正让它跑起来的是执行器的 poll、反应堆的唤醒和 Pin 划出的安全边界。*
