## 是什么

进程是操作系统**分配资源**的基本单位：一段独立的虚拟地址空间、一套文件描述符表、独立的权限凭据，崩了也不波及邻居。线程是 **CPU 调度**的基本单位：程序计数器、寄存器和栈，外加共享所属进程的全部资源。一句话直觉：进程像连锁店的各家分店，仓库各自独立；线程像同一家店里的几名员工，共用仓库和收银台，各管各的工位。所以浏览器给每个标签页一个进程（一个崩了，其他还活着），Web 服务则常在进程里开线程池（读写同一批数据不必来回搬运）。

## 核心原理

在 Linux 里，进程和线程并没有两套实现：它们都是 `task_struct`，创建时走的都是 `clone` 系统调用，区别只在传不传"共享"标志。`fork` 等价于不带共享标志的 `clone`，子进程拿到独立地址空间；`pthread_create` 底层同样是 `clone`，只是带上 `CLONE_VM`、`CLONE_FILES` 这类共享标志，新的只是执行流，地址空间和文件描述符表原样共享。可以把 `clone` 想成一张开店申请表：勾选的"共享资源"复选框越多，新生儿越像同事（线程）；一个不勾，就是新开一家分店（进程）。

这条分界线直接推出三大日常差异。

**创建与切换成本。** Linux 的 `fork` 用写时复制实现：不真拷贝内存，只复制页表、建一个 `task_struct`，创建本身已经不贵；但进程切换还要换页表，旧地址空间的地址翻译缓存（TLB）随之大多作废，之后的访存要重新预热——这才是进程切换比线程切换贵的根源（PCID/ASID 机制只能缓解，消不掉）。同进程的线程切换只需保存和恢复寄存器与栈指针，天然便宜。

**数据共享与同步。** 线程共享数据段和堆，一个线程改全局变量，其他线程立刻看得见，代价是必须上锁；进程彼此看不见内存，交换数据要走管道、共享内存、socket 这些 IPC。看一段接近真实行为的代码：

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

int counter = 0;
void *add(void *arg) { counter++; return NULL; }

int main(void) {
    pthread_t t;
    pthread_create(&t, NULL, add, NULL);
    pthread_join(t, NULL);
    printf("线程加一后: %d\n", counter);   /* 1，同一份内存 */

    if (fork() == 0) { counter = 100; _exit(0); }
    sleep(1);
    printf("子进程改成 100 后: %d\n", counter);  /* 仍是 1，写时复制 */
    return 0;
}
```

线程加的那 1 写在共享内存里，主线程看得见；子进程写下的 100 落在写时复制出来的私有副本上，父进程的 `counter` 纹丝不动。

**崩溃半径。** 一个线程段错误，整个进程一起陪葬，因为大家住在同一片地址空间里；进程崩了只烧自己，隔离就是用这份冗余换来的。

## 常见考点与误区

- **考点一："进程切换为什么比线程切换贵？"** 高频错误是答"因为进程装的东西多"。真正的差别只在地址空间：换页表导致 TLB 失效、缓存局部性变差；保存恢复寄存器这点开销，两者都要付。
- **考点二："多线程程序里 fork，子进程里有几条线程？"** 很多人答"整组复制"，实际只有调用 fork 的那一条，而且当时被别的线程持有的锁会原样复制成"永久上锁"，子进程再碰它就死锁——所以 fork 之后应尽快 exec。
- **误区三："线程一定比进程省、比进程好。"** 不成立。要强隔离、高容错（浏览器标签页、Nginx 的 master-worker）就用进程；要高频共享数据才用线程。选型看的是共享多还是隔离多。
- **考点四："Linux 里线程有 PID 吗？"** 每条线程有自己的 TID（`gettid` 可取），同一线程组共享进程 ID。网上说"Linux 没有线程，只有共享资源的进程"方向没错，但面试照 POSIX 语义回答更稳。

## 实践建议

- 把不可信输入和易崩模块拆成子进程：解析器、插件、渲染各一个进程，崩了主进程重启即可，错误半径天然可控；强共享的数据计算留在进程内的线程池里。
- 多线程程序里 fork 后立即 exec，不要让子进程"继承业务继续跑"；确要做预拷贝式快照，先想清楚锁和线程状态也被一并复制了。
- 用 `vmstat` 的 cs 列或 `pidstat -w` 观察每秒上下文切换：CPU 密集任务的线程数贴近核数即可，切得越多，算力浪费越多；确需进程间共享大数据，用共享内存而不是来回传拷贝。
