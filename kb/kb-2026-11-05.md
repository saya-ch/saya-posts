## 是什么

位置编码（Positional Encoding）是把“第几个 token”写进模型表示的那层机制。Transformer 的自注意力对输入顺序是置换等变的：把一句话打乱，注意力算出的结果只是跟着换位置，模型本身分不出“猫追狗”和“狗追猫”。所以必须在词向量或注意力分数里额外注入位置信息。一句话直觉：位置编码是发给每个 token 的座位号，但模型真正要学会的不是座位号本身，而是“这两个人隔了几排”。

它决定的不是模型“能不能读长文”，而是模型“读长文时还分不分得清远近”。典型场景包括长文档摘要、跨文件代码理解、多轮对话，以及 RAG 拼接出来的超长上下文。

## 核心原理

先看最经典的正弦编码。第 pos 个位置、第 i 维的编码是 sin(pos / 10000^(2i/d))，偶数维用 sin、奇数维用 cos。不同维度对应不同频率：低频维度波长大，位置走很远相位才转一圈；高频维度波长短，相邻 token 就能区分。这像一把刻度尺，高频是毫米刻度、低频是米刻度，组合起来既能量近处也能量远处。它还有个漂亮性质：位置 pos+k 的编码可以由 pos 的编码乘一个旋转矩阵得到，所以内积天然带相对位移信息。

RoPE（旋转位置编码）把这个性质做进了注意力。它不往词向量上加任何东西，而是把 q 和 k 按各自位置旋转一个角度，第 i 对维度的角度是 pos × base^(-2i/d)，base 通常取 10000。旋转后 q_m 与 k_n 的内积只与 m-n 有关：绝对位置被“编码进旋转”，相对位置在内积里“显形”。

```python
import torch

def rope(x, pos, base=10000.0):
    d = x.shape[-1]
    inv = base ** (-torch.arange(0, d, 2).float() / d)
    ang = pos[:, None] * inv[None, :]
    c, s = ang.cos(), ang.sin()
    x1, x2 = x[..., ::2], x[..., 1::2]
    return torch.stack([x1 * c - x2 * s, x1 * s + x2 * c], -1).flatten(-2)

torch.manual_seed(0)
q0, k0 = torch.randn(1, 1, 8), torch.randn(1, 1, 8)
for m, n in [(5, 3), (105, 103), (1005, 1003)]:
    q, k = rope(q0, torch.tensor([float(m)])), rope(k0, torch.tensor([float(n)]))
    print(m - n, (q * k).sum().item())   # 三行输出几乎一致
```

三组位置的绝对坐标差了 100 倍，内积却几乎不变。这说明 RoPE 的注意力分数只认相对距离——但也埋下了外推的隐患：模型训练时只见过 0 到 L 这一段相对距离，超出 L 之后，每个维度旋转出的相位组合是全新的，注意力没有任何经验可依。

更具体地说，base 取 10000 时，最低频维度的波长约为 2π×10000，量级在六万 token 左右，正好覆盖常见训练长度。一旦序列远超它，低频维度进入“没转过几圈却已偏出训练分布”的区域；高频维度则转得太多圈，两个相距很远的 token 在小数点后的相位上几乎无法区分，出现混叠。表现出来就是注意力 logits 整体漂移、softmax 变得异常尖锐、熵塌缩，模型要么只盯着最近的几个 token，要么被某个无关位置吸走。

于是有了几条扩展路线。位置插值（PI）最直接：既然没见过的位置是问题，就把位置坐标整体除以扩展倍数 s，把 0 到 sL 压回 0 到 L，让模型只面对见过的区间，再补少量微调恢复分辨率——原论文用不到 1000 步把 LLaMA 类模型扩到 32768。代价是所有距离都被等比压缩，近距离的分辨率下降，需要训练找回来。

NTK-aware 换了个方向：不动位置，动 base。把 base 放大到 base × s^(d/(d-2))，等于把每个维度的波长拉长，而且不同维度拉长的比例不同——高频维度几乎不动，低频维度大幅拉伸，相当于把“插值”的负担更多分给本来就不敏感的低频段。YaRN 在此基础上做分频段处理（NTK-by-parts），再给注意力分数加一个随扩展倍数变化的温度系数，抵消长序列上 softmax 过度尖锐的问题，论文报告比之前的方法少用 10 倍 token、少 2.5 倍训练步数。

把这几条路线放在一起看，本质是同一个权衡：位置分辨率与覆盖范围不可兼得。压缩坐标能覆盖更长区间，但相邻位置的相位差变小，模型更难分辨近处；拉伸 base 能保住近处，却让远处相位变化过慢，远距离的顺序信息变糊。YaRN 的分频段做法，就是承认不同维度该用不同策略：波长短于训练长度的维度保持原样，波长明显超出训练长度的维度才做插值，中间地带平滑过渡。

另一条路是 ALiBi：干脆不加位置向量，直接在注意力分数上减一个与距离成正比的惩罚 m×(i-j)，越远越吃亏。它没有可学习的绝对位置表，因此训练 1024、测试 2048 时困惑度仍然稳定，原论文的 1.3B 模型就是这样做的。代价是它把“近处更重要”写死成了归纳偏置，精确的远距离建模能力弱于专门调过的 RoPE。

## 常见考点与误区

- **误区一：RoPE 是绝对位置编码，所以不能外推。** RoPE 用绝对位置做旋转，但注意力分数只依赖相对位移，它是“绝对位置注入、相对位置生效”的混合体。能不能外推不取决于这个标签，而取决于频率设计和训练分布。
- **误区二：外推和插值是一回事。** 外推是让模型处理训练时没见过的位置坐标；插值是把新位置压缩回训练区间。PI、YaRN 本质都是插值加微调，工程口径里的“支持 128K”大多属于后者。
- **误区三：改个 base 或加个缩放就能免训练扩窗。** 动态 NTK 这类推理端技巧能缓解短倍率下的退化，但倍率一大，长距离检索和推理质量仍会掉；不继续训练就宣称“无损扩展”基本站不住。
- **误区四：标称 128K 就能用满 128K。** 有效上下文受训练数据长度分布、注意力实现、评测方式共同影响。needle-in-a-haystack 只测“能不能找到”，不测“找到之后能不能推理”。
- **考点：为什么 RoPE 只旋转 q 和 k，不旋转 v？** 位置信息只需要通过内积进入注意力权重；v 承载的是内容语义，旋转它反而会污染输出表示。
- **考点：ALiBi 为什么能“训短测长”？** 它把位置信息变成距离惩罚而不是可学习嵌入，模型学到的是一套与绝对长度无关的衰减规则；但外推能力仍有上限，且以牺牲远距离精确度为代价。

## 实践建议

- **先测瓶颈再改结构。** 用分区间困惑度、多位置 passkey retrieval、长文问答三组指标分别测 4K、16K、64K，确认是位置外推问题，还是训练数据里长距离依赖本来就稀疏。
- **按倍率选方案。** 2 倍以内的临时扩窗可以用动态 NTK 在推理端顶一下；要稳定上线，走 PI 或 YaRN 加继续预训练，训练步数几百到一千量级，同时保留原长度评测防止短文本退化。
- **把 scaling 参数当模型的一部分。** base、扩展倍数、温度系数必须写进模型配置并随权重一起发布，推理框架用默认值加载会让效果断崖式下跌。
- **算清长上下文的成本。** KV cache 随长度线性增长，prefill 是平方级注意力开销；上 GQA/MQA、分页 KV 和 KV 量化，比单纯堆显存更划算。
- **评测要防位置泄露。** 答案固定在开头或结尾会让分数虚高，把关键信息放在多个深度、加入干扰段落，才能看出模型是真的在用长上下文。
- **别把扩窗当成检索的替代品。** 上下文再长，注意力也会被无关段落稀释；先把检索做准、把 chunk 边界切好，再考虑扩窗，通常比直接堆到 128K 更便宜也更稳。

*一句话总结：位置编码解决的是“隔多远”，外推难在模型只学过训练长度内的那些距离。*
