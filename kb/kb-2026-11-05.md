## 是什么

注意力机制是 Transformer 的基本计算单元，也是现代大模型的"心脏"。它的标准形式叫缩放点积注意力：给定查询 Q、键 K、值 V，输出等于 softmax(QKᵀ/√d_k)·V。一句话直觉：这是一次**可微分的模糊检索**——拿着检索词（Q）去和每条记录的标签（K）打分，再按分数把所有记录的内容（V）加权混合回来。和数据库"返回最匹配的一条"不同，它返回软性的加权和，权重完全由前向计算产生，因此能放进梯度下降里一起学。场景无处不在：GPT 类自回归模型每一层都在做带因果掩码的自注意力，BERT 靠双向自注意力编码上下文，ViT 把图像切块后让块之间互相看，多模态模型用交叉注意力把文本查询对到图像区域。

## 核心原理

把注意力想成一次图书馆检索：Q 是你写下的检索词，K 是每本书书脊上的索引标签，V 是书里的正文。三份信息来自三个不同的线性投影——即便在自注意力里，Q、K、V 也都由同一个输入 X 乘上三组权重矩阵得到。为什么要拆成三份？因为"如何被找到"和"找到之后给什么"是两个独立的功能：打分发生在 Q 与 K 之间，聚合发生在权重与 V 之间。若直接拿原始向量既当键又当值，模型就失去了"把自己投影成另一种内容"的自由度。这套定义来自 Vaswani 等人 2017 年的论文 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)。

真正让面试官反复追问的是那个 √d_k。假设 q、k 的各分量独立同分布、零均值、单位方差，那么点积 q·k = Σᵢ qᵢkᵢ 的期望是 0，**方差是 d_k**。头维度为 64 时，打分的标准差约 8；softmax 的输入一宽，输出就逼近 one-hot：最大的分数吸收几乎全部权重，其余位置的梯度趋近于零，注意力在训练早期就"锁死"在个别 token 上。除以 √d_k 把方差拉回 1，让 softmax 停在灵敏区，[d2l.ai 的推导](https://d2l.ai/chapter_attention-mechanisms-and-transformers/attention-scoring-functions.html)给出了这个方差论证。注意：softmax 的工程实现本来就会减去最大值来防 exp 溢出，所以"除以 √d 是为了防溢出"站不住——它保的是分布形状和梯度，不是数值上限。

```python
import math, random

def softmax(xs):
    m = max(xs)
    e = [math.exp(v - m) for v in xs]
    s = sum(e)
    return [v / s for v in e]

random.seed(0)
d = 64                                              # 头维度
q = [random.gauss(0, 1) for _ in range(d)]
keys = [[random.gauss(0, 1) for _ in range(d)] for _ in range(4)]

def attention_weights(scale):
    s = [sum(q[i] * k[i] for i in range(d)) / scale for k in keys]
    return [round(w, 3) for w in softmax(s)]

print("除以 √d :", attention_weights(math.sqrt(d)))  # 权重分散
print("不缩放  :", attention_weights(1.0))           # 接近 one-hot
```

多头则是把 d_model 切成 h 份子空间（512/8=64），每个头在自己那 64 维里独立完成打分与聚合，最后拼接并过一次输出投影。所以多头不是"把注意力算 h 遍"：参数量与单头全维大体同量级，[Jay Alammar 的图解](https://jalammar.github.io/illustrated-transformer/)把这套拆分讲得最直观。代价集中在另一处——打分矩阵是 n×n，一层自注意力的计算量是 O(n²·d)，序列翻倍，打分成本约翻四倍。自回归推理用 KV cache 缓解：每层历史的 K、V 存下来不重算，新 token 只拿自己的 Q 与缓存里的 K 做点积；省下了重复计算，显存却随序列长度线性上涨。

## 常见考点与误区

- **考点一：为什么要除以 √d_k，不除会怎样**。答方差：点积方差随维度线性增大，softmax 输入过宽会饱和成近似 one-hot、梯度消失。答"防溢出"或笼统的"数值稳定"只能得一半分——softmax 实现里减最大值已经处理了溢出问题。
- **误区二："注意力权重等于人类注意，可视化就是解释"**。权重只是归一化的分数，不保证与语义对齐；不少头的权重在对角线上占主导（自己看自己），拿注意力图直接下结论很容易翻车。
- **考点三：复杂度到底是不是 O(n²)**。训练与预填充阶段，打分矩阵 n×n，是 O(n²·d)；配了 KV cache 的自回归解码，每步新增计算只有 O(n·d)，但显存随序列长度线性增长。两个说法经常被混着用，面试里要分开答。
- **误区四："多头注意力就是并行算 h 遍"**。多头的正确理解是切分子空间，d_k = d_model/h；若保持每头 64 维再多开几个头，才是真的增加计算与参数。
- **考点五：为什么必须有位置编码**。注意力对输入顺序置换等变：打乱 token 顺序，各位置的输出只是跟着换位置，内容不变。没有位置编码，模型眼里只有集合，没有序列。

## 实践建议

- 手写或排查注意力时先核对两处：scale 用的是 √(head_dim) 而不是 √d_model；掩码在 softmax **之前**加 −∞，而不是之后置零——顺序错了，padding 位置会混进权重里。
- 做长上下文推理预算时，先算 KV cache 的显存账：层数 × 序列长度 × KV 头数 × 头维 × 2（K 与 V）× 精度字节数，这一项常常比模型权重先撞墙；GQA/MQA 正是通过让多个查询头共享 KV 头在这里省显存。
- 显存 OOM 时先想序列长度：打分矩阵对 n 是平方级敏感，优先考虑分块、稀疏注意力或截断上下文，而不是一味砍 batch 硬扛。
- fp16/bf16 训练遇到 loss 尖刺，先查 softmax 附近的数值再怪学习率：打分矩阵的量纲与精度，是常见却容易被跳过的排查点。

*一句话总结：注意力是可微分的软检索——Q、K、V 解耦"怎么找"与"给什么"，除以 √d_k 保的是梯度与分布形状，不是数值安全。*
