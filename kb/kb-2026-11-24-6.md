## 是什么

路径总和是给定一棵二叉树和一个目标和，判断是否存在一条从根节点到叶子的路径，使路径上所有节点值之和恰好等于目标和。它的一句话直觉是：把“当前这条从根到节点的路径”当成一个可以压栈、可以弹栈的账本，走到叶子时结算，退回父节点时把这一笔划掉。最典型的场景是决策树里判断预算能否刚好用完，以及在一棵目录树或表达式树上收集满足约束的完整链路。

对应 LeetCode 的 [112 题](https://leetcode.cn/problems/path-sum/) 与 [113 题](https://leetcode.cn/problems/path-sum-ii/)：前者只返回布尔值，后者要求返回所有满足条件的路径，也正是“回溯”真正登场的地方。需要先分清，[437 题](https://leetcode.cn/problems/path-sum-iii/) 那种“方向向下、不必到叶子”的路径计数是另一类问题，不能照搬本文的模型。

## 核心原理

先看一条不变量：调用 `dfs(node, remain)` 时，`path` 里装的恰好是从根到 `node` 的父节点这条链，`remain` 等于目标和减去这条链的和。进入函数后把 `node.val` 追加进 `path`、让 `remain` 减去它，不变量就在 `node` 这一层继续成立。若 `node` 是叶子且 `remain` 为 0，就把当前 `path` 记为一个答案；无论是否命中，函数返回前都要把 `node.val` 弹出。

拿一棵常见的树走一遍：根 5，左 4、右 8；4 的左孩子 11，11 的孩子是 7 和 2；8 的孩子是 13 和 4，这个 4 的左孩子是 5、右孩子是 1，目标和为 22。走到 7 时路径是 `[5,4,11,7]`，剩余 -5，不是答案，弹出 7；再走 2，剩余 0，命中，记下 `[5,4,11,2]`，随后依次弹出 2、11、4，回到根。此时列表已经回到 `[5]`，再进右子树才能得到干净的 `[5,8,4,5]`。如果左子树返回时没有弹干净，右子树的路径就会以 `[5,4,11,2]` 开头，答案直接串味。

这里的关键不是递归，而是“撤销”。递归调用会为每一层保存局部变量，像 `remain` 这种整数在函数返回时会自然恢复成调用前的值；但 `path` 是一个在堆上共享的列表对象，所有递归层拿到的是同一个引用，函数返回并不会把它还原。换句话说，调用栈只负责恢复“每层自己的小本子”，不负责恢复大家共用的那块白板。少了 `pop`，左子树走过的节点会留在列表里，等右子树再往里加，最后收集到的路径就是两条分支拼出来的脏数据；如果只在成功分支 `pop`，失败分支返回时同样会留下残留。

这也解释了为什么 112 题看起来像回溯却常常不写 `pop`：它只把布尔结果往上传，不维护任何跨分支共享的路径，栈帧退出时状态自然消失。回溯只在“需要把一条具体路径留到叶子、再带回根”时才真正必要。

同样重要的是“快照”。当命中叶子时写 `res.append(path)`，存进去的是列表的引用而不是当时的内容。后续的回溯会继续 `pop` 同一个列表，等整棵树走完，结果集里所有元素都指向那个已经被清空的列表，于是打印出来是一堆空数组。正确做法是 `res.append(path.copy())`，在命中的一瞬间把内容固定下来。

```python
def path_sum(root, target):
    res, path = [], []

    def dfs(node, remain):
        if node is None:
            return
        path.append(node.val)
        remain -= node.val
        if node.left is None and node.right is None:
            if remain == 0:
                res.append(path.copy())   # 快照，不是引用
        else:
            dfs(node.left, remain)
            dfs(node.right, remain)
        path.pop()                        # 与 append 严格对称

    dfs(root, target)
    return res
```

复杂度要分两部分看。每个节点只进出一次，这部分是 O(N)；但每次命中叶子都要复制一条长度为 O(H) 的路径，最坏可以把总代价推到 O(N²)（例如一条长脊上每隔几个节点挂一片叶子）。递归栈与 `path` 各占 O(H)，H 是树高；输出本身的大小也要计入，不能只说 O(N)。

## 常见考点与误区

- **把“到叶子”写成“到空节点”**：在 `node is None` 时判断 `remain == 0`，会把“只有一个孩子”的节点的缺失子树当成叶子。比如根为 1，左孩子为 2，2 还有一个左孩子 0，目标和为 3；在 2 的缺失右子树处 `remain` 恰好为 0，就会把 `[1,2]` 当成答案，而 2 并不是叶子。叶子的定义必须是 `left` 与 `right` 同时为空。
- **结果集存引用而不是拷贝**：这是路径收集题最高频的翻车点，现象是返回 `[[], [], []]` 或最后一条路径重复多遍。只要结果里出现“所有答案长得一样”，先查 `append` 的是不是 `path` 本身。
- **只在成功分支撤销**：113 里命中后直接 `return`，`pop` 就永远不会执行；下一次进入兄弟分支时 `path` 还带着上一条路径。要么统一在函数末尾 `pop`，要么用 `try/finally` 保证每条返回路径都清理。
- **用 `remain < 0` 剪枝**：节点值可能为负，目标和也可能为负，路径和会先降后升。此时“剩余为负就剪掉”会漏解。只有确认所有节点值非负，这个剪枝才成立；更稳的界是“剩余节点值的最大可能贡献”。
- **把 112 的短路写法直接搬到 113**：112 找到一条就能逐层返回 true，不需要维护路径；113 必须走完整棵树，而且每层都要恢复状态。两者骨架相似，退出条件与状态管理完全不同。
- **以为可以随便加记忆化**：对“是否存在”可以按 `(node, remain)` 记忆；对“枚举所有路径”不行，因为同一个 `(node, remain)` 在不同前缀下对应不同答案，缓存会吞掉路径。437 那种计数则换用前缀和加哈希表，是另一套思路。

## 实践建议

- 写回溯先写三行骨架：“做选择、递归、撤销选择”，并让撤销与选择严格对应。`path.append` 配 `path.pop`，`visited.add` 配 `visited.remove`，计数器加一配减一；任何一处不对称，都会在某个兄弟分支上暴露。
- 收集答案一律做快照。`path.copy()` 只在该命中时付一次复制成本；如果图省事写成 `path + [node.val]`，代码更短、也不容易漏 `pop`，但每个节点都要复制一次，空间与常数都会变差。
- 先把边界问清楚再动手：空树返回什么、单节点算不算路径、是否必须根到叶子、节点值与目标值能不能为负。面试里主动确认“根到叶子”这四个字，往往比多写十行代码更能避免返工。
- 深树要防递归栈溢出。可以把递归改成显式栈，栈元素保存 `(node, remain, 进入/退出标记)`，退出标记负责 `pop`；这样状态恢复仍然成立，但代码复杂度会上升，非必要不换。
- 自测别只测一条链。构造一棵“左链很长、右子树另起一条”的树，检查右分支结果有没有混进左分支的节点；再用节点数不超过 8 的随机树，暴力枚举所有根叶路径对拍，能很快抓出漏 `pop` 与提前 `return` 的问题。
- 输出可能非常大时不要先攒一个大列表。用回调或生成器把每条命中路径交给调用方消费，避免 O(N²) 的路径副本同时驻留内存；如果确实要返回全部结果，就在复杂度分析里如实说明这部分成本。

*一句话总结：路径总和的分水岭不是会不会递归，而是返回父节点之前，有没有把这一步真正撤干净。*
