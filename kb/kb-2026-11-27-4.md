## 是什么

模型量化是把 FP16 或 BF16 的张量映射到更低位宽，用少量缩放参数换回近似值。INT8 与 FP8 都落在 8 位，但可表示的集合完全不同：INT8 是整数格，FP8 是浮点格。可以把 INT8 想成一把 256 格的等距尺子，每格一样宽；FP8 则像一把对数尺，靠近零的格密、远离零的格疏，却能一路量到很大的数。

它出现的场景很集中：权重、激活与 KV Cache 的 8 位存储，W8A8 矩阵乘，端侧和 CPU 上的 INT8 推理，Hopper/Ada 上的 FP8 推理与训练。这里的 W8A8 指权重和激活都量化到 8 位，矩阵乘直接吃低位输入；W8A16 只量化权重，计算前还要反量化回 16 位，主要省显存和带宽，不省算力。量化也不是一种文件格式，而是一组映射参数加一套 kernel 约定，同一个模型完全可以有不同配方。面试里常从“W8A8 和 W8A16 有什么区别”“E4M3 与 E5M2 怎么选”“per-tensor 和 per-channel 差在哪”切进来。两者不是新旧替代关系，而是两种不同的舍入策略：一个用均匀刻度换分辨率，一个用指数换动态范围。

## 核心原理

先看 INT8。仿射量化写成 `x̂ = s(q − z)`，其中 `q` 是 `[−128, 127]` 内的整数，`s` 是步长，`z` 是零点。对称量化令 `z = 0`，只剩一个 scale；非对称量化保留零点，能更好覆盖全正或全负的激活。关键在于 `s` 通常由张量里绝对值最大的元素决定：`s = amax / 127`。只要有一个 48 的离群值混在一堆 ±3 的激活里，步长就被撑到 0.378，绝大多数值只剩十几个格，舍入误差按同一把尺子放大。补救办法是把尺子做细：权重按输出通道 per-channel，激活按 token per-token；或者用 [SmoothQuant](https://arxiv.org/abs/2211.10438) 把激活的离群难度离线迁移到权重上，再做 W8A8 INT8。per-channel 之所以有效，是因为每个输出通道各有一条 scale，某个通道的离群值不会把其他通道的步长一起撑大；代价是 scale 数量变多，kernel 要按通道取参数，布局不友好时反而会拖慢。[LLM.int8()](https://arxiv.org/abs/2208.07339) 则走另一条路：把少数离群特征维度留在 16 位，其余 99.9% 的值走 8 位。

FP8 把 8 位拆成 1 位符号、4 或 5 位指数、3 或 2 位尾数。按 [NVIDIA 的 FP8 文档](https://docs.nvidia.com/deeplearning/transformer-engine-releases/release-2.19/examples/fp8_primer.html)，E4M3 最大可表示 ±448，尾数 3 位，相邻格点的相对间隔最粗约 `2^-3`；E5M2 最大可表示 ±57344，尾数 2 位，相对间隔约 `2^-2`。它没有零点这个参数，因为浮点格式本身就有精确的 0；它只需要一个 scale 把张量搬进 FP8 的动态范围。这个设计来自 [FP8 Formats for Deep Learning](https://arxiv.org/abs/2209.05433)：E4M3 放弃 inf、只留一个 NaN 编码，把省下的编码让给数值范围。

因为格点非均匀，FP8 的精度是“相对”的：1.0 附近能分辨约 0.125，64 附近能分辨约 8，但 0.01 这样的小值仍然保留自己的指数，不会被离群值一把推成 0。per-tensor INT8 的绝对步长则是全局统一的，小值和大值共用同一格；per-channel、per-token 只是把“全局”缩小到一组，并没有改变步长均匀这件事。也正因如此，FP8 并不是免校准：E4M3 最大只有 448，张量 amax 超过它就必须先缩放；per-tensor 一个 scale 仍会被极端离群值拉低分辨率。MXFP8 把缩放粒度缩到每 32 个元素一个 E8M0 的 2 的幂 scale，才让 E4M3 在训练中覆盖大多数张量。

所以“谁更准”没有统一答案。分布紧凑、近似高斯的权重，INT8 的 8 位均匀分辨率通常优于 E4M3 的 4 位有效精度；重尾激活、梯度这类跨数量级的张量，FP8 的指数更抗离群。粒度是第三个变量：per-channel INT8 可能比 per-tensor FP8 更准，per-block FP8 又可能反超。下面这段纯 Python 只做标量模拟，不模拟次正规数，但足以看清分水岭：

```python
import math, random
random.seed(0)
base = [random.gauss(0, 1) for _ in range(4096)]
def q_int8(v):
    s = max(map(abs, v)) / 127
    return [max(-127, min(127, round(t / s))) * s for t in v]
def q_e4m3(v):
    s = max(map(abs, v)) / 448
    out = []
    for t in v:
        y = t / s
        e = math.floor(math.log2(abs(y))) if y else -9
        step = 2.0 ** (e - 3)
        out.append(max(-448, min(448, round(y / step) * step)) * s)
    return out
def rel(v, q):
    return math.sqrt(sum((a-b)**2 for a, b in zip(v, q)) / sum(a*a for a in v))
for name, v in [("无离群", base), ("一个 48 离群", base + [48.0])]:
    print(name, "int8=%.4f" % rel(v, q_int8(v)), "e4m3=%.4f" % rel(v, q_e4m3(v)))
```

在没有离群值时，INT8 的相对误差约为 0.008，E4M3 约为 0.027，INT8 明显更准；加入一个 48 的离群值后，INT8 升到 0.088，E4M3 反而降到 0.022。这不是说 FP8 天生更好，而是说离群值把 INT8 的固定步长撑坏了，而 FP8 的指数替它接住了这个大值。

还有一层常被忽略：格式能不能变成速度，取决于指令。在 NVIDIA 这条线上，INT8 张量核从 Turing 起就有，Ampere、Ada、Hopper 一路支持；FP8 的原生矩阵乘要到 Ada/Hopper，也就是 compute capability 8.9 起，在 Turing/Ampere 上只能走 W8A16 的权重反量化，省显存但不省算力。在 vLLM 这类框架里，[FP8 文档](https://docs.vllm.ai/en/latest/features/quantization/fp8.html)把这条边界写得很清楚。Blackwell 又反过来：[vLLM 的 INT8 文档](https://docs.vllm.ai/en/latest/features/quantization/int8.html)明确，compute capability 10.0 及以上的 Blackwell 不再支持 INT8 路径，要改用 FP8。此外 INT8 GEMM 通常用 INT32 累加，FP8 GEMM 通常用 FP32 累加；累加器精度、缩放因子的施加位置、转置布局都会影响 kernel 选择。

## 常见考点与误区

- **“位宽一样，精度就一样”**：8 位只是存储宽度。INT8 有 256 个等距格点，E4M3 只有约 4 位有效精度；但在重尾分布上，FP8 的指数能把大值小值分开，实际误差反而更小。面试要答“看分布与粒度”，不能只背位宽。
- **“INT8 就是除以 127”**：漏了零点、裁剪和粒度。激活常是非对称的，GELU、SiLU 的输出并不以零为中心，零点不能随便省；per-tensor 与 per-channel 的误差可能差一个数量级；TensorRT 走对称量化，不代表所有 INT8 实现都对称。
- **“FP8 不需要校准”**：FP8 仍需 scale。静态 per-tensor 要校准 amax；动态 per-token 每步算 min/max，精度好但有额外开销。E4M3 没有 inf、只有一个 NaN 编码，未缩放溢出不会给你一个显眼的 inf，可能直接变成 NaN 或错误值。
- **“有离群值就无脑上 FP8”**：per-tensor FP8 仍是一个 scale，极端离群值会把其余值压进次正规区；块缩放、per-channel、SmoothQuant、混合精度都是候选。先看离群值出现在权重还是激活、是固定通道还是偶发。
- **“量化一定更快”**：解码是带宽瓶颈，W8A16 也可能明显加速；prefill 是计算瓶颈，没有原生 8 位张量核的卡上，反量化开销会把收益吃掉。小 batch、动态量化、kernel 不支持，都会让理论算力落不了地。
- **“校准集随便抓几百条”**：校准分布必须贴近线上：同模型 chat template、同语言、同序列长度。vLLM 的 INT8 文档建议从 512 条、序列长度 2048 起；太小可能漏掉真实长尾，amax 估低，上线后被迫裁剪；太大又容易被极端值抬高 amax，把大多数值压进更粗的格子。
- **“E5M2 比 E4M3 更高级”**：E5M2 范围大但尾数只有 2 位，精度更低。训练里前向权重与激活用 E4M3、反向梯度用 E5M2，是拿范围换梯度不溢出，不是全模型都用 E5M2。
- **“只比 perplexity 就够了”**：困惑度对长上下文、代码、数学、罕见 token 不敏感；要跑任务级 eval、KL 散度、长上下文和边界输入，并保留回退。

## 实践建议

- 先看卡再选格式：Hopper、Ada、Blackwell 优先 FP8 W8A8；Turing、Ampere 用 INT8 W8A8 配 SmoothQuant，或者用 FP8 W8A16 省显存；Blackwell 上先确认框架是否还支持 INT8，别把 Hopper 的调优参数直接搬过去。
- 不要一上来就追 W8A8：先做 weight-only 8 位，确认显存与精度收益，再决定要不要量化激活。权重分布稳定、量化风险低；激活随输入变化，才是误差的主要来源。
- 权重 per-channel，激活 per-token；INT8 激活有固定离群通道就用 SmoothQuant 或混合精度；FP8 优先动态 per-token 缩放，追精度再上 per-block，但要确认 kernel 真的支持，否则只是把开销换了个地方。
- 校准从 512 条、序列 2048 起，匹配线上 chat template 和语言分布。INT8 用 percentile 裁剪而不是硬取 max，FP8 用 amax 时留一点余量；校准后同时看 KL 散度和任务指标，不能只看 loss。
- 敏感层留在 BF16/FP16：embedding、lm_head、第一层与最后几层、LayerNorm 和 Softmax。KV Cache 量化单独评估，长上下文下误差会沿层累积，别把它和权重量化混成一个开关。
- 把量化配方当成版本管理的一部分：记录校准集、scale 文件、kernel 后端和评测结果；换模型、换卡或换序列长度分布时重新校准，不要直接复用上一版权重。
- 验收用真实流量：固定 batch 与序列长度分布，比较 TTFT、TPOT、goodput、显存峰值和任务准确率；先灰度一小部分流量，准备好一键回退，再谈全量替换。

*一句话总结：8 位只决定了盒子大小；INT8 卖均匀刻度，FP8 卖动态范围，选型要同时看分布、粒度与显卡。*
