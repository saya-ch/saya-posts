## 是什么

平衡二叉树（height-balanced binary tree）的定义只有一句话：对树中任意一个节点，它的左右子树高度之差的绝对值都不超过 1。空树高度记为 0，叶子高度记为 1。换句话说，它不是“根节点看起来不歪”，而是“每一棵子树都得自己过关”（[LeetCode 110](https://leetcode.cn/problems/balanced-binary-tree/)、[Emory 的 AVL 讲义](http://www.cs.emory.edu/~cheung/Courses/253/Syllabus/Trees/AVL.html)）。

这个性质的重要性在于它把树高钉在了对数级。AVL 树正是把这个条件当成不变量，Cornell 的讲义给出最小节点数的递推 N(h)=N(h−1)+N(h−2)+1，解出来 N(h) ≥ φ^h，所以 n 个节点的 AVL 树高度不超过 log_φ n，约 1.44 log₂ n（[Cornell 讲义](https://www.cs.cornell.edu/courses/cs2112/2015fa/lectures/lec_avl/)）。树高是对数级，查找、插入、删除的最坏路径才是 O(log n)。

典型场景：面试题判断一棵二叉树是否平衡；反序列化或导入数据后做结构校验；测试里检查索引树有没有退化。要区分两个概念：**平衡**只描述形状，**二叉搜索树**描述节点值的有序性。AVL 是“二叉搜索树 + 每个节点平衡因子不超过 1”，而单独一棵平衡二叉树完全可以是无序的。

## 核心原理

判平衡的第一步不是写递归，而是想清楚“高度从哪边来”。高度是节点到最远叶子的边数（或节点数），要从叶子往上数，所以天然适合后序遍历；深度是根到节点的距离，从根往下数，才适合前序。面试里把高度和深度说反，后面的复杂度和递归方向通常也跟着错。

先看最直观的写法：对每个节点，分别求左右子树高度，比较；然后再递归判断左右子树。思路没错，但同一个子树的高度会被反复计算。设一条 n 个节点的链，根求高度要走 n 步，第二层要走 n−1 步，依此类推，总工作量是 n+(n−1)+…+1，也就是 O(n²)。如果树本来就很平衡，同一层的子树规模加起来仍是 O(n)，而层数是 O(log n)，总工作量大约是 O(n log n)。所以这种写法的复杂度要分情况说：链状树最坏 O(n²)，平衡树约 O(n log n)，不能笼统说成 O(n²)，更不能说成 O(n)。

优化思路是把“求高度”和“判平衡”合并成一次后序递归：函数返回这棵子树的高度；如果子树已经不平衡，就返回一个不可能的高度（常用 −1）当哨兵。父节点拿到左右结果后，先看有没有 −1，有就直接上抛，不再计算另一侧；否则比较两边高度，差超过 1 也返回 −1，最后返回 `max(left, right) + 1`。

可以把它想成工地上的脚手架验收：每个班组先量自己这一段的高度，报给上一层；哪一段已经歪了，上一层拿到“不合格”的标记就没必要再派人去量，直接往上报。整棵树验收完，没有出现不合格标记，才算平衡。

```python
class Solution:
    def isBalanced(self, root):
        def height(node):
            if node is None:
                return 0
            left = height(node.left)
            if left == -1:
                return -1
            right = height(node.right)
            if right == -1:
                return -1
            if abs(left - right) > 1:
                return -1
            return max(left, right) + 1

        return height(root) >= 0
```

这段代码每个节点只进入一次，时间复杂度 O(n)；递归栈的深度等于树高，空间复杂度 O(h)。对平衡树 h=O(log n)，但对一条链 h=n，这也是后面要讲的工程风险。

为什么“每个节点”这四个字不能省？构造一棵根节点通过、子节点失败的树：根 R 的左子树是一条长度为 3 的链，右子树是一条长度为 2 的链，根本身左右高度差是 1，看起来合格；但左子树的根 L，它的左子树高度是 2、右子树高度是 0，差是 2，L 已经不合格。只要有一个节点不合格，整棵树就不平衡。递归定义的意义就在这里：每个节点的左右子树也必须是平衡二叉树（[Emory 讲义](http://www.cs.emory.edu/~cheung/Courses/253/Syllabus/Trees/AVL.html)）。

还有一个容易忽略的细节：−1 能不能当哨兵，取决于高度怎么定义。如果按“节点数”定义、空树高度为 0，合法高度都是非负的，−1 安全；如果按“边数”定义、空树高度为 −1，那么 −1 本身就是合法高度，哨兵会和不平衡标记撞车。这时候要换成 `None`、一个 `(balanced, height)` 二元组，或者干脆换一种高度定义。面试时主动说出这个前提，比背代码更加分。

## 常见考点与误区

- **只判断根节点**：这是最常见的错。根节点左右差 1，只能说明根这一处合格；上面那棵“左链 3、右链 2”的树就是反例。正确说法是“对每一个节点都成立”，或者等价地“左右子树都是平衡二叉树，且根节点左右高度差不超过 1”。
- **把高度差当成节点数差**：平衡看的是高度，不是节点个数。一棵 7 个节点的完美二叉树高度是 3，一条 7 个节点的链高度是 7，节点数一样，高度差 4；反过来，左边 7 个节点、右边 3 个节点也可能高度只差 1。用节点数判平衡，会把明显退化的树放过去。
- **把平衡树、二叉搜索树、完全二叉树混成一件事**：平衡只约束高度；二叉搜索树约束中序有序；完全二叉树约束除最后一层外每层填满、最后一层靠左。完全二叉树一定平衡，但平衡二叉树不要求完全。判断完全二叉树用的是层序编号，不是高度差。
- **复杂度答成“每个节点求高度就是 O(n²)”**：不准确。链状树是最坏 O(n²)，平衡树约为 O(n log n)；只有把高度和判定合并成后序一次遍历，才是稳定 O(n)。面试官追问“为什么”时，要能写出那条 n+(n−1)+… 的式子。
- **哨兵用错**：高度按边数定义、空树为 −1 时，−1 是合法值，不能拿来标记不平衡；另外最后判断写成 `height(root) > 0` 会把空树判成不平衡，空树按定义是平衡的，应该用 `>= 0`。
- **以为红黑树也满足 AVL 条件**：红黑树靠颜色和黑高约束把树高压在对数级，但不要求每个节点左右高度差不超过 1。拿 AVL 的判定函数去跑一棵红黑树，返回 false 是正常的；它仍然是一棵合法的红黑树。反过来，AVL 判定通过也不代表这棵树是红黑树。
- **把“判定”当成“维护”**：判定只读，不会旋转；AVL 的插入和删除要在回溯路径上更新高度并做 LL、RR、LR、RL 旋转。面试里问“怎么判断”却答成“怎么旋转”，是答非所问。

## 实践建议

- 面试就写后序 + 哨兵：先判空，再求左，左不平衡立刻返回，再求右，右不平衡立刻返回，最后比较高度。把“为什么可以先返回”讲清楚——整棵树已经确定不平衡，继续算另一侧的高度没有意义。
- 处理不可信输入或可能很深的树时，不要直接递归。一条十万节点的链会让递归栈达到十万层，Python 默认限制下会直接 `RecursionError`，调大限制也可能撞上解释器的 C 栈。改用显式栈的迭代后序，或者在入口先限制最大深度。
- 明确需求再选指标：要 AVL 的严格条件就用本文的逐节点高度差；要判断完全二叉树就用层序编号；要验证红黑树就检查 BST 有序、根为黑、红节点不能有红孩子、每条路径黑高相同。三套检查不能互相替代。
- 如果树在插入删除后还要一直保持平衡，别每次操作后重跑 O(n) 判定，而是在旋转和回溯时维护高度或平衡因子，把代价摊到每次修改上；判定函数留给测试、导入校验和故障排查。
- 测试用例至少覆盖：空树、单节点、纯左链、纯右链、根平衡但内部失衡、节点值无序的树，以及一棵较大的链。小规模随机树可以和 O(n²) 的朴素实现做对拍，用朴素实现当 oracle，能很快抓出哨兵和边界错误。

*一句话总结：平衡二叉树判的是每一棵子树的高度差，后序一次遍历把高度和结论一起往上带，才是 O(n) 的解法。*
